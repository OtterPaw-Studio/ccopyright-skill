# ccopyright-register

> 把软件代码仓库整理成一套可复核的普通计算机软件著作权登记准备材料。

[English](README.en.md) · [快速上手](#快速上手) · [会准备哪些材料](#会准备哪些材料) · [产物目录](#产物目录) · [安全与边界](#安全与边界)

ccopyright-register 帮助申请人从软件代码仓库出发，准备、检查和整理软著登记材料。你可以直接在 AI 编程 Agent 中提出需求；它会分析仓库、询问代码无法证明的申请事实，并在仓库内建立结构化的 **.ccopyright/** 复核工作区。

它服务于向[中国版权保护中心](https://www.ccopyright.com.cn/)人工提交之前的材料准备环节，不登录账号、不自动填写网页、不提交申请、不跟踪进度，也不解析补正通知。

## 为什么需要它？

准备软著材料并不只是导出六十页代码。软件名称、版本、著作权人、日期、申请表字段、源码选择和说明文档必须相互一致，且要能回溯到登记版本。

这个 Skill 可以帮助你：

- 在不改写业务源码的前提下盘点仓库；
- 用一个可编辑文件维护申请人确认的事实；
- 按门户顺序准备可复制的申请表填写底稿；
- 以明确顺序选择可追溯的第一方源码；
- 生成程序和文档鉴别材料；
- 用且仅用 **INFO** 与 **WARNING** 输出仓库、权属、知识产权和敏感内容预检；
- 在本机工具可用时渲染并技术校验 A4 PDF；
- 在人工复核后发布带校验和、不会覆盖旧版本的新修订。

## 快速上手

### 1. 通过 skills.sh 安装

仓库已经采用标准的嵌套 Skill 结构，**skills** CLI 能够发现且只发现一个 Skill：**ccopyright-register**。

从 GitHub 安装（仓库可访问后）：

~~~bash
npx skills add OtterPaw-Studio/ccopyright-skill --skill ccopyright-register
~~~

全局安装到 Codex：

~~~bash
npx skills add OtterPaw-Studio/ccopyright-skill \
  --skill ccopyright-register \
  --agent codex \
  --global
~~~

如果已经克隆到本地，可以立刻从仓库根目录安装：

~~~bash
npx skills add . --skill ccopyright-register
~~~

**skills** CLI 可以直接通过 **npx** 运行，无需单独全局安装。详见 [skills.sh CLI 文档](https://www.skills.sh/docs/cli)。

### 2. 用 Agent 打开要申请软著的软件仓库

如果你还在判断登记边界，可以先只做评估：

~~~text
使用 $ccopyright-register 评估这个仓库是否适合准备普通软著登记。
先不要生成材料，请列出建议的软件身份、源码边界、缺失事实和全部警告。
~~~

也可以直接开始准备：

~~~text
使用 $ccopyright-register 为这个仓库准备软著登记材料。
先创建 .ccopyright 工作区并生成草稿，只询问代码无法安全确定的事实。
~~~

面向登记提交的填写底稿和鉴别材料默认使用中文。

### 3. 最终生成前确认申请事实

Skill 会请你确认 Git 历史无法证明的信息，包括：

- 软件全称、可选简称和精确版本；
- 著作权人名称及顺序；
- 开发完成与发表事实；
- 原始/继受取得、全部/部分权利和开发方式；
- 程序、文档均为普通交存；
- 源程序量及其统计口径；
- 本次申请对应的当前门户要求。

草稿可以保留待复核标记。必填事实和确认项未完成前，Skill 不会生成最终材料。

### 4. 渲染、校验并发布一个复核版本

本机具备 Chrome/Chromium 和 Poppler 后，可以这样要求：

~~~text
使用 $ccopyright-register 执行最终生成，渲染两份 PDF，完成技术校验并生成逐页接触表。
先告诉我还需要哪些人工检查，在我明确确认之前不要发布 ready 版本。
~~~

## 前置依赖

缺少可选 PDF 工具时，Skill 仍然可以扫描仓库、生成底稿和 HTML。

| 依赖 | 用途 | 是否必须 |
|---|---|---|
| 支持 Agent Skills 的 AI 编程 Agent | 执行引导式工作流 | 必须 |
| 带 **npx** 的 Node.js | 通过 skills.sh 安装 | 仅安装时需要 |
| Python 3.10 或更高版本，命令名为 **python** | 仓库扫描、底稿、清单、HTML 和校验编排 | 必须 |
| Chrome 或 Chromium | 把 HTML 鉴别材料渲染成 PDF | 生成 PDF 时需要 |
| Poppler 的 **pdfinfo** 与 **pdftotext** | PDF 技术校验 | 校验 PDF 时需要 |
| Poppler 的 **pdftoppm** | 逐页 PNG 和接触表 | 可选 |
| Git | 记录快照来源和检查未提交修改 | 推荐但非必须 |

可以让 Skill 运行环境预检，也可以在已安装 Skill 的目录中执行：

~~~bash
python scripts/ccopyright.py preflight
~~~

本地生成器不要求 LLM API Key、门户密码、身份证明或签名证书。

## 你需要准备什么

代码仓库可以提供实现证据，但不能决定全部申请事实。建议提前准备或确认：

1. 要登记的仓库和精确版本；
2. 申请人认可的软件名称与著作权人；
3. 开发完成和发表事实；
4. 开发方式与权利取得分支；
5. 哪些第一方源码允许披露；
6. 文档类型以及需要纳入的真实产品截图；
7. 当前门户说明，或与内置基线不同的已脱敏截图；
8. 合同、授权或其他条件证明是否已在仓库外准备好。

不得把证件号码、证件扫描件、签名、门户账号凭据、Cookie 或未脱敏的门户截图放入工作区。

## 完整使用流程

| 阶段 | Skill 会做什么 | 你需要复核什么 |
|---|---|---|
| 评估 | 扫描清单、源码、Git、文档、截图、许可证、生成/依赖区域和敏感模式 | 候选版本、第一方边界、警告 |
| 初始化 | 创建 **.ccopyright/** 和 schema v2 事实文件 | 推测值保持未确认 |
| 草稿 | 生成填写底稿、证明清单、源码/文档材料、追溯清单和证据映射 | 门户字段、文案、源码顺序、缺失证据 |
| 最终生成 | 要求事实完整、确认完成且使用普通交存 | 软件身份、日期、权利、字数和条件分支 |
| 渲染与校验 | 生成 PDF，检查 A4、页/行身份、规范字段、哈希和待确认标记 | 通过接触表检查每一页 |
| 发布 | 人工明确确认后创建新的时间戳 ready 版本 | 本次真正需要上传的文件 |

警告只提供复核建议，不会演变成第三种风险等级。最终生成仍可能因必填事实缺失或材料约束不满足而停止；这属于完整性门禁，不是法律风险判断。

## 会准备哪些材料

### 申请表填写底稿

按门户顺序生成中文填写底稿，覆盖当前可见字段：

- 软件身份与分类；
- 原创或修改软件；
- 开发方式；
- 权利取得方式与范围；
- 开发完成和发表事实；
- 六项开发/运行环境；
- 编程语言与源程序量；
- 开发目的、行业、主要功能和技术特点；
- 程序/文档一般交存；
- 著作权人与共同享有状态。

截图可见的字数限制和条件分支由带日期的规则快照驱动。当前门户要求始终优先于随附基线。

### 程序鉴别材料

Skill 根据显式选择的第一方文件构造有序源码流，保留空行、注释、制表符、内容与顺序。追溯清单会把每个打印行映射回原路径、原行号、源码流位置和哈希。

支持提交全部材料或普通交存的前、后连续窗口，不处理例外交存。

### 文档鉴别材料

Skill 会把申请人认可的文档章节、仓库证据和真实产品截图组织为确定性材料。缺少依据的描述会产生警告；它不会虚构产品功能，也不会用套话填充页数。

### 条件证明材料清单

清单会根据合作开发、委托开发、下达任务、修改软件、继受取得和部分权利等分支动态变化。这里只记录是否准备，证明 PDF 始终保留在代码仓库之外。

## 产物目录

默认在软件仓库内创建 **.ccopyright/**：

~~~text
.ccopyright/
├── facts/                 唯一申请事实和规则快照
├── reports/               仓库清单、预检、证据、构建和渲染报告
├── drafts/                可复制填写底稿与人工清单
├── work/                  Markdown、HTML、PDF、图片和追溯清单
├── qa/                    校验报告、逐页图片与接触表
└── ready-to-submit/       不覆盖旧内容的时间戳复核版本
~~~

通常需要上传的是程序/文档鉴别材料 PDF，以及当前门户要求的表单或证明文件。追溯清单、证据映射、哈希和接触表默认只用于内部复核，除非门户明确要求。

## 安全与边界

这个 Skill：

- 不填写或提交浏览器表单；
- 不登录、签字、缴费或操作申请人账号；
- 不跟踪申请，也不解析补正通知；
- 不判断权属，不保证登记通过；
- 不从 Git 推断著作权人、完成日期、发表事实或源码披露权限；
- 不保存证件号码、证件扫描件、签名、账号凭据或会话数据；
- 不自动处理例外、封存、涉密或军用交存流程。

仓库/知识产权预检只有 **INFO** 与 **WARNING**。所有产物都属于材料准备辅助，不构成法律意见。

## 常见问题

### 没有 Chrome 或 Poppler 能使用吗？

可以。仓库评估、事实管理、填写底稿、追溯清单、Markdown 和 HTML 都可使用；PDF 渲染与技术校验需要前置依赖表中的可选工具。

### 每个 WARNING 都必须处理完才能生成吗？

不需要。警告会保持可见，但本身不阻断生成。必填事实缺失、门户字段约束不满足、选择了不支持的例外交存，或 PDF 校验失败，会阻断对应的最终阶段。

### Skill 会判断软件属于谁吗？

不会。它只记录申请人确认的权利事实并提示证据边界。权属和证明文件是否充分仍由申请人负责。

### 可以复用仓库中已有的说明书吗？

可以，而且优先复用持续维护的真实文档。重要描述应尽量映射到实现或其他仓库证据。

### 会把合同或身份证明上传进工作区吗？

不会。Skill 只生成准备状态清单，这些文件始终保留在 **.ccopyright/** 之外。

### 内置的门户字段一定是最新的吗？

不一定。它们来自部分表单截图基线和维护的官方参考。把规则快照标记为当前有效之前，必须复核本次申请实际看到的门户。
