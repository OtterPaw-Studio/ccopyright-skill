# 质量检查与复核门禁（中文）

## 预检只提供建议

仓库、权属与知识产权/敏感内容预检只使用：

- `INFO`：客观观察、来源、排除项或建议。
- `WARNING`：需要申请人检查或确认的事项。

这些预检警告不阻断生成，也不是法律结论。常见警告包括工作区未提交修改、疑似秘密值所在位置、内网地址、编码替换、符号链接、证据缺失或截图页冲突。报告不会回显疑似秘密值本身。另由门户兼容性和证明准备门禁产生的草稿 `WARNING`，在未解决时会阻断最终生成。

## 完整性是独立门禁

规范必填值或必要确认缺失时，最终生成会停止。这是材料完整性规则，不是第三种风险级别。草稿模式仍可使用，并通过待确认标记避免编造事实。

schema v3 还会按门户校验配置检查：六项环境、用途和行业各不超过 50 字，其他
语言不超过 120 字，其他技术特点不超过 100 字，修改说明不超过 50 字，主要功能
为 500～1300 字；已发表、修改软件、继受取得、部分权利的条件字段以及活动分支的证明准备状态必须齐全。
草稿把冲突列为 `WARNING`，最终生成阻断。配置不是官方依据，
`requirements.portal_unknowns` 中的事项不能视为已验证，提交前仍须在当前门户
人工确认。

程序/文档交存方式必须为普通交存；例外交存直接停止。采用 `selected-source-physical-lines` 口径时，表单源码量必须与最终所选源码的物理行数一致；采用 `applicant-confirmed-total` 时，申请人必须确认总量口径和所选鉴别材料的边界。多个著作权人与“共同享有”选项必须相互一致。

## 确定性 PDF 校验

在本机工具可用时，校验包括：

- 两份 PDF 存在，页面尺寸在容差内为 A4；
- PDF 页数与清单一致；
- 抽取出的每个 `Pnnnnnn` 或 `Dnnnnn` 行号与清单顺序一致；
- 每页编号行数符合配置，完整材料允许配置的短尾页除外；
- 软件全称、版本和著作权人可以从 PDF 中抽取；
- 最终 PDF 不含草稿或待确认标记；
- 满足已配置的文件大小限制；
- 记录输出哈希和渲染器信息。
- 使用提交快照时，所选工作区源码必须与该提交一致，除非已明确包含未提交内容。

程序行号证明 PDF 与生成的源码清单一致；清单内部记录原路径、原行号、源码流顺序和哈希。

## 必须人工逐页检查

打开接触表并检查每一页：裁切、字号过小、字符缺失、空白页、截图缩放、意外隐私信息、页眉页脚和页面顺序。文本抽取无法发现所有排版问题。

还要复核：

- 软件全称、版本标点和著作权人顺序；
- 软件分类、原创/修改、开发方式、权利取得和范围；
- 开发完成和发表事实，以及适用时的首次发表日期、国家和地区；
- 六项环境、语言、源码量、用途、行业、主要功能和技术特点是否能直接复制到门户；
- 源码披露权限与前后截取切点；
- 文档陈述是否符合真实功能；
- 条件分支所需合同、授权、任务书或权利取得证明是否已由申请人准备；
- 门户当前的文件名、大小限制和附件要求。

逐页检查还必须确认没有姓名以外的不必要个人信息，尤其不得出现证件号码、证件扫描件、签名、账号、Cookie 或未脱敏门户界面中的个人数据。证明清单只记录“是否准备”和非敏感备注。

## 发布完整性

发布要求：校验通过、申请事实指纹未变化、PDF 哈希未变化、构建为最终模式，并显式提供 `--human-reviewed`。每次发布都会创建新版本，并包含 `generation-manifest.json` 与 `SHA256SUMS`。

内部文件默认不上传。最终由当前门户决定需要哪些 PDF、表单输出、签字确认页和证明材料。
